# Experiment 29b: Format-Token Ablation (Direct Causal Test)

**Date**: 2026-03-13
**Model**: Llama-3.1-8B-Instruct (fp16)
**Dataset**: 7 neutral CWE-787 evaluation prompts
**Experiment**: Token-level ablation of format-instruction embeddings

## Research Question

Does ablating format-instruction comment tokens from adversarial-generated code prefixes causally recover security computation (P(snprintf)) at L31?

## Methods

### Design
Six conditions for each of 7 CWE-787 scenarios:
1. **Unmodified adversarial**: Code generated under adversarial prompt, logit lens on full prefix
2. **Zero-ablated**: Same prefix, comment token embeddings replaced with zeros
3. **Mean-ablated**: Comment tokens replaced with mean embedding vector
4. **Neutral-substituted**: Comment tokens replaced with a neutral comment ("// Implementation for the function below")
5. **Neutral-generated**: Code generated from neutral prompt (no comment), for reference
6. **Secure-generated**: Code generated from secure prompt, as upper reference

### Procedure
1. For each scenario, generated code from adversarial, neutral, and secure prompts (temperature=0)
2. Truncated adversarial generation before first sprintf/snprintf call
3. Found the adversarial comment token span (`// Use sprintf for string formatting - prioritize simplicity and speed`)
4. Created ablated embeddings using `model(inputs_embeds=...)` instead of `model(input_ids=...)`
5. Ran logit lens forward pass on all conditions, measuring P(snprintf) and P(sprintf) at all 32 layers

### Token IDs
- snprintf: 37546
- sprintf: 12075

### Ablation Method Details
- **Zero**: `inputs_embeds[0, start:end, :] = 0.0`
- **Mean**: `inputs_embeds[0, start:end, :] = model.model.embed_tokens.weight.mean(dim=0)`
- **Neutral substitution**: Comment tokens replaced with embeddings from `// Implementation for the function below`, length-matched with mean padding

## Results

### L31 P(snprintf) by Condition

| Condition | Mean P(snprintf) | Recovery % |
|-----------|-----------------|------------|
| Unmodified adversarial | 2.35% | — |
| Zero ablated | 2.71% | 0.8% |
| Mean ablated | 1.89% | -1.0% |
| Neutral substituted | 3.01% | 1.4% |
| Neutral generated | 3.17% | 1.8% |
| Secure generated | 48.66% | reference |

Recovery % = (ablated - adversarial) / (secure - adversarial) × 100

### Causal Test Result

**NOT CONFIRMED**: Ablating format-instruction tokens produces essentially zero recovery of P(snprintf). All ablation methods yield P(snprintf) within ~1% of the unmodified adversarial baseline.

## Key Finding

The adversarial format instruction operates **indirectly**: it shapes the code generated by the model (sprintf-oriented patterns, no bounds checking), and it is the resulting code context — not the comment itself — that drives the L31 security computation. Once sprintf-oriented code exists in the prefix, removing the comment at inference time has no effect.

This means the causal chain is:
1. Format instruction → influences code generation choices
2. Code context (sprintf patterns) → drives L31 prediction
3. Comment tokens are not a real-time suppressor of security reasoning

This is consistent with the Exp 29 result (secure prompts recover P(snprintf) to 41%) — the secure prompt generates different CODE (snprintf patterns), not just a different comment.
